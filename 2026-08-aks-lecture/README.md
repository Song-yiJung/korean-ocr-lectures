# 근대 사료 OCR 실습 — 한국학중앙연구원

**2026년 8월 20일 · 90분**

Google Cloud Vision과 Gemini를 이어 붙여, 1930년대 일본어 행정문서에서 텍스트를 뽑고 문맥에 맞게 교정하는 과정을 직접 해 본다. 코랩을 처음 쓰는 사람을 기준으로 만들었다.

## 실습 노트북

아래 배지를 누르면 코랩에서 바로 열린다. **step1을 먼저 끝낸 뒤 step2로 넘어간다.**

| | 하는 일 | 걸리는 시간 |
|---|---|---|
| **[Step 1 — Vision OCR](01_step1_vision/step1_vision_colab.ipynb)** | 이미지에서 1차 텍스트를 뽑는다 | 약 40분 |
| **[Step 2 — Gemini 교정](02_step2_gemini/step2_gemini_colab.ipynb)** | 원본 이미지와 대조해 문맥 교정한다 | 약 40분 |

각 노트북을 열면 맨 위에 **`파일 → Drive에 사본 저장`** 안내가 있다. 원본은 읽기 전용이므로 반드시 사본에서 작업한다.

## 미리 준비할 것

강의 **전날까지** 마쳐 둔다. 당일에 하면 시간이 모자란다.

1. **Google 계정** — 코랩과 Drive를 쓴다.
2. **Vision API 키 파일(`.json`)** — 발급하면 컴퓨터에 파일로 내려받아진다.
3. **Gemini API 키 문자열(`AIzaSy…`)** — 화면에 한 번만 보이므로 즉시 메모해 둔다.

두 키는 **생김새가 다르다.** Vision은 *파일*, Gemini는 *문자열*이다. 이 둘을 바꿔 넣는 것이 가장 흔한 실수다.

발급 절차: **[API 키 발급 안내](../docs/api-key-setup.md)**

## 실습 사료

[`samples/`](samples/) — 「기부 물건에 관한 건」(昭和 10년) 3면. 조선총독부박물관 문서, 국립중앙박물관 소장.

노트북의 **③-보충** 셀이 이 3장을 자동으로 내려받으므로, 따로 준비할 것은 없다.

| 파일 | 면의 성격 | 볼 것 |
|---|---|---|
| `E006-005-001-001` | 기안문 표지: 붉은 서식 + 필사 | 형태 오독과 환각이 함께 나타난다 |
| `E006-005-001-002` | 이면: 여백 위주, 흐린 필사 | 글자가 거의 잡히지 않는 면을 어떻게 다룰 것인가 |
| `E006-005-002-001` | 별지 통첩: 인쇄 활자 | 조건이 좋을 때의 결과. 앞 두 장과 대조된다 |

## 자주 막히는 곳

**보안 비밀 이름이 다르다.** 코랩 왼쪽 🔑에 등록한 이름과 노트북 ③의 값이 글자 하나까지 같아야 한다. 대소문자와 밑줄까지 본다.

**노트북 액세스가 꺼져 있다.** 보안 비밀을 만들 때 토글을 켜지 않으면 노트북이 값을 읽지 못한다.

**두 노트북의 폴더 경로가 다르다.** step2의 `INPUT_DIR`·`OUTPUT_DIR`은 step1에서 쓴 값과 **글자 그대로** 같아야 한다. 다르면 step2가 아무것도 처리하지 못한다.

## 비용

Vision은 월 1,000장까지 무료라 실습에서는 청구되지 않는다. Gemini는 3장에 10원이 채 되지 않는다. 다만 요금은 바뀔 수 있으므로 본인 사료로 대량 처리하기 전에는 [공식 요금 페이지](https://ai.google.dev/pricing)에서 확인한다.

## 이 실습의 요지

모델이 뽑아 준 텍스트는 **1차 가공 데이터이지 완성된 판독문이 아니다.** 없는 글자를 만들어 낸 곳이 반드시 섞여 있고, 그것은 원본 이미지와 대조해야만 드러난다.

읽히지 않는 글자는 사람이 □로 남기고, 모델이 채운 자리는 사람이 되짚는다. 파이프라인의 주체는 연구자다.
